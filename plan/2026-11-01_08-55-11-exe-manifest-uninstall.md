## 当前执行范围：仅 install、update、uninstall

本节描述当前已实现的约定；文末方案复评记录采用预先管理范围的理由和实施结果，取代历史的逐文件归属规则。此前把审查中的恢复需求扩展为独立卸载产品、便携缓存迁移和 MSI 策略补齐，超出了用户要求的最小改动；以后先判断是否直接影响这三个操作，再增加机制。

### 保留的三个操作

| 操作 | 必需改动 | 继续复用 |
|---|---|---|
| `--install` | 从当前包取得完整路径列表，预先保存授权管理范围，再按最终名称安装；已有安装仅允许同目录重装，不先递归卸载。旧版无清单时须一次确认接管这些包路径，包括失败后卸载未覆盖的旧文件。 | 当前安装选项、首装目录选择、UAC、注册项及系统组件安装逻辑；已有安装沿用原目录。 |
| `--update` | 按包列表替换文件并更新归属；保留降级能力。完整同产品包成功后清理旧清单差集；通用包更新定制安装时保留包外旧文件及归属。 | 当前目录、选项、服务状态和系统组件更新逻辑，不重新实现 MSI 的状态保留体系。 |
| `--uninstall` | 仅删除清单中的文件、精确定位的固定生成物及允许清理的空目录；保留未知文件和链接，必要删除失败明确报告。 | 当前系统集成清理及提权入口；文件阶段替换现有整目录删除。 |

更新规则仍为：可信旧集合为 `O`，经过最终 EXE 名映射的新包集合为 `P`。完整替换成功后为 `P`；通用包更新定制安装成功后为 `O ∪ P`。后者不删除 `O − P`，也不新增逐文件来源登记。通用更新可能保留弃用文件，但这些条目继续参与卸载。

### 必需边界

- 只新增安装目录中的 `data/meta/install-manifest.json`。现有根目录 `meta.toml` 保持位置、格式和便携缓存用途，不拿它推断安装归属。
- 普通便携运行、Quick Support、缓存刷新、定制缓存清理及 MSI 路径保持现状。包装器只允许增加为上述安装/更新提供准确包列表所必需的薄接入，不以此为由迁移缓存或重写解包流程。
- 包列表来自合并后的 `BinaryReader.files`（`libs/portable/src/bin_reader.rs:31`、`:45`），不扫描解包目录或安装目录认领文件，也不将 `package_paths` 当成完整列表。保留来源验证和受保护暂存；复用 `src/platform/windows/installer_files.rs:39`，不新增永久第二份包清单或完整安装包缓存。
- 包内路径映射到实际安装名称后再计算集合。通用更新读取经验证的旧定制配置；完整定制包使用自身配置，不能被 `prepare_custom_client_update` 覆盖或删掉新配置。产品、根、架构及 EXE/MSI 归属检查保留，包版本高低不作为拒绝条件。
- 首次安装可选择目录；已有 EXE 安装（含旧版确认迁移）的目标根须经路径/目录身份核验，与可信注册信息中的安装根一致。另选目录在停止服务、写文件或改注册项之前拒绝，不把它当作首装，不把旧清单套到新目录，也不新增目录迁移功能。
- 路径必须是合法相对路径；拒绝 `..`、绝对路径、Windows 路径别名冲突、控制文件覆盖和 symlink/junction/reparse point。检查覆盖根、父目录链和叶子对象；不能以“先检查、后按字符串删除”冒充竞态防护。链接保留并报告，不遍历链接目标。
- RuntimeBroker、固定快捷方式继续按可信根与已有固定名称定位，不增加登记表；不存在视为已处理，其他必要操作错误不吞掉。
- 在任何已安装负载或组件变更前，原子写入经预检和授权的 `O ∪ P`；失败保留范围，成功再按更新类型收敛。保留操作互斥、目标核验与错误传播，不扩展为跨文件回滚、自动修复或后台恢复系统。记录缺失、不可读、损坏或格式不兼容时，`--uninstall` 在任何变更前报错，不能当作空清单或转用旧递归卸载。
- 旧版首次迁移确认绑定本次包、根及覆盖范围；取消或静默缺少显式授权时，在停止服务/变更目标文件前退出。继续使用已定的迁移选项，不另加配置页面、FFI 接口或长期授权记录。
- 首次迁移确认并成功保存清单后，全部包路径即受管理，即使尚未覆盖也参与卸载；重试依据管理范围，不再保存逐项许可或发布日志。旧 v1 清单的非空 pending/migration 字段在预检时报错，须先使用对应旧包完成操作；空字段只为兼容读取，新清单不再写出。

### 卸载执行方式的最小验证

实施前的 master `94c321d05` 中，`get_uninstall` 在 `src/platform/windows.rs:1903` 递归删除安装目录，`run_cmds` 已有受保护提权及等待逻辑（`src/platform/windows/installer_handoff.rs:100`）。这些基线位置说明原接入点；当前 EXE 递归删除分支已移除。

1. 在停止进程/服务、清理系统组件或修改文件/注册项之前，读取并验证产品、安装根和清单。真正旧版无清单也拒绝直接卸载；须先按既定 `--install` 显式确认迁移，未接管的包外历史文件仍保留，不扫描补出清单。
2. 系统组件清理仍在应用文件删除前通过原有专用逻辑执行，不把这些实现复制进新卸载程序。卸载注册项（含 `InstallLocation`）及清单保留至受管文件和必要系统组件均清理成功；不能照搬 `src/platform/windows.rs:1901` 提前删除注册项的顺序，否则自定义目录会失去 `src/platform/windows.rs:1495` 使用的定位信息。
3. 验证既有执行链能否完成运行中 EXE/DLL 的退出后清理、目录链约束及真实结果报告；不能只把 `rd /s` 换成一批 `del`，也不能把启动清理进程当作卸载成功。
4. 若复用需要一个额外执行载体，只限定为执行清单文件操作的最小辅助程序；先记录为何现有入口无法承担，再单列必要源码/构建接入。不默认新增安装器框架、ARP 入口、永久恢复缓存或完整应用副本。
5. 采用用户已确认的完整安装包重试方案。部分卸载失败后可能无法从已安装应用再次启动；卸载注册信息、清单及未完成信息必须保留。重试需要支持本清单格式、产品匹配的完整安装包（定制安装须有匹配的定制包），重新执行 `--uninstall` 只处理原清单范围，不扫描认领残留。该限制必须明确告知，不能声称无需源包恢复。

仅在上述文件和必要系统组件清理成功后，才删除清单、卸载注册项并收尾空目录。最终控制信息清理不是跨资源事务；此时失败应报告具体控制残留，不假报全部完成，也不以缺失清单为由重新执行普通卸载。不新增专用收尾状态机。

## 元数据、复用与历史依据

现有 `meta.toml` 只记录便携缓存时间戳与部分定制文件，缓存刷新会重写它；它既不代表完整包，也不代表经授权的安装管理范围。保留其原用途，安装清单单独放在 `data/meta/install-manifest.json`，避免改变便携与 MSI 的既有消费者（`libs/portable/src/main.rs` 的元数据读写及 `setup`）。

复用现有 `serde` / `serde_json` / `windows` 与受保护暂存实现，不引入新的安装框架。[cap-std](https://docs.rs/cap-std/latest/cap_std/fs/struct.Dir.html) 和 [Velopack](https://docs.rs/crate/velopack/latest) 是调研候选，当前未采用。MSI 的产品边界、文件清单和固定生成物清理可参考仓库 `res/msi/Package/` 与 `res/msi/CustomActions/CustomActions.cpp`；其完整回滚、修复及版本准入规则不加入本次 EXE 实现。

已废弃的完整方案与早期调研保留在 [首个实现提交的计划文档](https://github.com/fufesou/rustdesk/blob/b632390dc/plan/2026-11-01_08-55-11-exe-manifest-uninstall.md)，不再在当前计划重复维护。

## 方案复评：先确定管理范围，再执行文件操作（已实施）

### 判断与依据

- 原方向正确，但原计划没有充分区分“按包路径管理文件”与“只认领实际成功发布的文件”。后者是更强的行为约定，不是安全删除天然要求的唯一实现；此前把它当成不可改变的需求，导致优化只停留在局部去重。以后先明确失败时的用户可见结果，再评估状态和代码成本。
- 当前 `69fb890eb` 相对 master 涉及 35 个文件、增加 4,245 行及删除 134 行（含计划）。22 个新 Rust 模块共 3,711 行，其中非测试 2,937 行。文档和文件拆分不能完全解释这个规模；管理员端到端和 Win7 仍未验收，不能用模块测试替代流程验证。
- 直接证据（以下引用均指 `69fb890eb`）：`manifest_files/files.rs:22` 为单项发布写入 pending，再登记归属；`:90` 每删除一项再次写清单。`manifest_files/pending.rs:19`、`:47` 恢复发布归属；`install_manifest/migration.rs:26`、`:65` 保存并校验尚未发布的旧文件覆盖许可。它们共同服务于“未发布就不归属”的约定；后两个模块已在本轮删除。

### 当前方案：单份清单记录已授权管理的路径

清单仍位于 `data/meta/install-manifest.json`，但含义改为“已授权由此安装管理的路径”，允许条目对应的文件尚不存在。`O` 是此前管理集合，`P` 是本次包按最终名称映射的集合；只有完成所有预检及必要确认后，才将 `U = O ∪ P` 原子写入清单。原子替换、目录句柄与权限检查继续复用；不实现跨文件回滚。

| 操作 | 简化后的顺序 |
|---|---|
| install / update 共用准备 | 验证可信包内容、产品/根/架构、EXE/MSI 归属、路径树、链接、权限及目标冲突；迁移按下述新语义确认。执行侧取得操作锁并重新核验根、清单和目标身份，然后在首个已安装文件变更或组件命令前持久化 `U` 及操作状态、保留定位信息。 |
| install、完整包 update（含降级） | 按原有停止/组件顺序发布全部 `P`；全部发布成功后才删除 `O − P`。组件流程也成功后，将清单收敛到 `P` 并标记完成。任何一步失败保留 `U` 和未完成结果。 |
| 通用包 update 定制安装 | 发布 `P`，保留 `O − P`；成功清单仍为 `U`。继续复用原目录、选项和组件流程。 |
| uninstall | 先验证清单与所有目标；组件清理成功后持久化 `Uninstalling`，再按清单逐项删除。文件已缺失视为已处理，不逐项缩减清单；必要删除全部成功才删除控制记录与注册项，最后清理允许清理的空目录。 |

安装失败后的文件集合可能是新旧混合，清单并不声称安装成功。用户可用匹配的完整包重试或卸载；重试重新执行包文件操作。保留现有卸载阶段标记，避免重试调用已删除的程序清理组件。空目录归属记录暂不改，不能把取消逐文件归属写入说成整个安装只写一次清单。

### 已确认的行为变化

旧版迁移确认从“允许本次覆盖这些同名旧文件”扩大为“从现在起由安装器管理这些包路径，包括后续替换与卸载”。确认并成功保存 `U` 后，即使一个文件尚未覆盖、安装就失败，卸载也可以删除该范围内的旧文件。包外未受管文件仍保留；取消、静默缺少授权或预检失败不会接管旧文件。普通已有清单安装遇到范围外同名文件仍拒绝，不能借本方案自动认领。

用户本轮已选择 “Adopt confirmed paths before copying (recommended for the smaller design)”。该选择批准调整设计；应用实际迁移时仍须取得一次确认，并让提示明确上述接管含义，不能把此前仅批准覆盖的旧记录自动解释为扩大后的许可。这不是等价重构；“未发布旧文件不参与卸载”不再是新方案的要求。

### 失败边界与保留机制

| 失败位置 | 持久范围与可见结果 |
|---|---|
| 预检/确认失败，或 `U` 原子写入未成功 | 不执行组件命令或变更已安装负载。首装准备可能留下空目录或明确报告的控制暂存残留，不声称所有准备动作都无副作用。 |
| `U` 成功后，发布、组件或过期文件删除失败 | 清单保留 `U`；已完成动作不回滚，明确报告未完成。重试/卸载都有范围依据，不再推断单个文件是否发布成功。 |
| 文件完成但最终清单提交失败 | 仍按 `U` 和未完成状态处理；重试时允许已删除的过期项缺失，不假报成功。 |
| 卸载组件、阶段记录或文件删除失败 | 保留清单和定位信息。阶段记录提交前不删除应用文件；提交后重试跳过组件阶段，缺失文件直接继续。 |
| 文件清理成功后，控制记录/注册项收尾失败 | 报告具体残留。维持现有限制：最终收尾不是跨文件与注册表事务，不新增恢复产品。 |

- 保留：路径/别名及链接拒绝、根与父链约束、受保护暂存及摘要校验、原子记录、操作锁、固定 RuntimeBroker/快捷方式定位。暂存控制槽仍需验证受保护目录和对象后清理；删除 pending 不等于允许扫描删除任意 `.tmp`。
- 保留现有文件辅助程序和构建接入。改为运行应用副本会重新引入 DLL 依赖、进程退出和部分卸载后的启动问题；本轮没有更小且验证过的替代，不为减少文件数改写执行链。
- 不改普通便携缓存及 `meta.toml`，不引入安装框架。用 MSI 承载 EXE 安装会改变产品归属；现有 `windows.rs:1634` 明确拒绝 EXE 覆盖 MSI，`res/msi/Package/Package.wxs:46` 也有另一套升级策略，不能作为兼容既有 EXE 降级行为的小改动。
- 格式兼容须单独核对：已有 v1 清单可能包含未完成的 pending/migration 记录，不能假设此分支从未使用或直接忽略字段。完成记录和旧未完成记录分别验证；无法安全转换时明确要求用对应包先完成操作，不按版本高低拒绝。若要求旧未完成记录直接迁移，所需兼容成本计入净减量。
